  • November 27th, 2026: Rewrote the CHtmlToText class, which converts a web page into the plain text that is indexed:
    • It no longer uses MFC and it keeps no state between calls, so one instance can be reused and shared by several threads. It runs in linear time and without recursion, so hostile or truncated pages cannot exhaust the stack;
    • Inline elements no longer split words (<b>H</b>ello is now Hello), while block elements, <br>, list items, table rows and table cells keep the text apart;
    • An <img> inside <noscript>, or a <param> inside <object>, no longer hides the rest of the page, which used to drop the footer, the categories and the language links of many pages;
    • The title and the content of the elements that are not displayed (script, style, noscript, template, object, svg, math, iframe, textarea, canvas, audio and video), the comments and the CDATA sections are no longer indexed;
    • A lone <, as in a < b, is text and no longer the start of a tag, and a > inside a quoted attribute value no longer ends the tag;
    • White space, including the no-break space and the other Unicode spaces, is collapsed (it is preserved inside <pre>), and every malformed UTF-8 byte is replaced with U+FFFD.
  • November 27th, 2026: Rewrote the UnquoteHTML function, which decodes the character references in the title and in the text of a web page before they are stored in the database. Its declaration moved from WebSearchEngineExt.cpp to the new UnquoteHTML.h header:
    • It follows the HTML5 specification: HtmlEntities.h, generated by GenerateHtmlEntities.py from the WHATWG list, has all 2,125 named references (the old table only had the 251 of HTML 4.01), and the 106 of them that browsers accept without the semicolon, such as &copy and &amp, are decoded without it as well;
    • Text that only looks like a reference is no longer lost: AT&T and Q&A used to become AT and Q. A &# that is not followed by a number, and a name that browsers do not accept without the semicolon (&hellip), stay as written;
    • Numeric references: the semicolon is optional and the number can have any number of digits (&#4294967361; used to wrap around and become A). &#0;, the surrogates and the values above U+10FFFF become U+FFFD instead of a NUL or an invalid sequence, and &#128; to &#159; are the Windows-1252 characters (the euro sign, the curly quotes, the ellipsis) that browsers show;
    • The characters above U+FFFF, such as &#x1F600;, are encoded correctly; they used to be cut to 16 bits;
    • &nbsp; and every other reference to a Unicode space (&#160;, &ensp;, &#x3000;) now give an ordinary space, like the spaces that CHtmlToText collapses; &nbsp; used to be a space, but &#160; was a no-break space;
    • The result is always well-formed UTF-8, because every malformed byte of the input is replaced with U+FFFD. A title in Latin-1 or Windows-1252 no longer makes the conversion to UTF-16 throw a bad conversion exception;
    • It keeps no state between calls (the old one built a global table on its first use, which is not safe with several threads) and it runs in linear time.
  • November 27th, 2026: Reimplemented the utf8_to_wstring and wstring_to_utf8 functions, which convert text between UTF-8 and the UTF-16 strings of Windows and of the database. They moved from WebSearchEngineExt.cpp to the new Utf8.h and Utf8.cpp files:
    • They no longer use std::wstring_convert and std::codecvt_utf8: the <codecvt> header has been deprecated since C++17 and C++26 removes it, and the standard library of MSVC has no replacement yet. The new code takes std::string_view and std::wstring_view and is written with the C++20 and C++23 library (std::countl_one, std::span, constexpr, basic_string::resize_and_overwrite), so it needs /std:c++latest, which the project already uses. The _SILENCE_CXX17_CODECVT_HEADER_DEPRECATION_WARNING definition of stdafx.h is gone;
    • They never throw. Malformed UTF-8 used to throw a bad conversion exception, which nothing caught in the crawling thread, so a link with an accented letter (the links are kept in the ANSI code page) could end the program. Now every ill-formed sequence becomes U+FFFD, one for each maximal subpart, as the Unicode Standard and the WHATWG Encoding Standard prescribe. The old code also accepted the overlong forms and the encoded surrogates;
    • The characters above U+FFFF, such as emoji, are converted to and from UTF-16 surrogate pairs. The old code cut them to 16 bits when it decoded them, and it wrote the two halves of a pair as two 3-byte sequences (CESU-8), which is not UTF-8. A surrogate without a partner becomes U+FFFD;
    • The tables use the MySQL character set utf8, which cannot store the characters above U+FFFF, and ProcessHTML stops the crawl when the server refuses a row. So ProcessHTML now replaces each of these characters in the URL, the title and the text of a page with U+FFFD (replace_supplementary_characters) before it stores them. The replacement can be removed once the tables are converted to utf8mb4;
    • The conversion keeps no state between calls, so it is safe to call from several threads, and the static_assert tests at the end of Utf8.cpp check it every time the file is compiled.
